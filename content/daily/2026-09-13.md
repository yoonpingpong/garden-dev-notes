# 2026-09-13

## 학습한 내용

Spring Boot 4.1.1 + Gradle Kotlin DSL 보일러플레이트 실험 중 나온 빌드 설정 질의응답을 정리했다.

- io.spring.dependency-management 플러그인을 주석 처리하면 좌표 끝에 콜론만 남고 버전이 비어 빌드가 실패한다 → BOM이 채워 주던 것
- plugins는 빌드 도구(기계), dependencies는 산출물에 들어가는 라이브러리(부품). 스프링 부트는 양쪽에 다 등장한다
- 롬복이 compileOnly와 annotationProcessor 두 줄인 이유 — 애노테이션 타입 참조와 코드 생성은 별개

Spring 설정 클래스 주제도 이어서 정리했다.

- @EnableJpaAuditing을 메인 클래스에 두면 웹 슬라이스 테스트의 컨텍스트 로드가 깨진다. jpaAuditingHandler → jpaMappingContext → JPA metamodel must not be empty 연쇄
- 실패를 가른 것은 @Configuration의 스캔 여부가 아니라 애노테이션이 붙은 위치다. 처음 세운 인과를 스택 트레이스로 정정했다
- @Configuration은 XML 설정의 자리이고, 인터페이스 구현체 지정은 그중 한 용도일 뿐이다
- @Configuration은 프록시라서 @Bean 메서드끼리 호출해도 싱글턴이 유지된다. @Component는 그냥 new 한다
